# SC-500 Azure API Management Demos

This lab demonstrates a small, low-cost API architecture: an Azure Function provides an HTTP backend and Azure API Management (APIM) is the public API gateway. APIM enforces subscription-key authentication, separating backend application logic from gateway security policy.

[Open the interactive lab](https://brave-coast-05f5d1003.6.azurestaticapps.net)
or follow the [complete presenter and deployment guide](docs/agent-token-limit.md)
for both the Function subscription-key demo and the Foundry agent token-limit demo.

## Architecture

```text
Client
   |
   | HTTPS
   v
+---------------------------+
| Azure API Management      |
|                           |
| API Gateway               |
|                           |
| - Subscription key        |
+---------------------------+
            |
            v
+---------------------------+
| Azure Function App        |
|                           |
| GET /api/hello            |
+---------------------------+
```

## Purpose

Use this reproducible demonstration to show that API gateway controls can be changed without putting APIM-specific security code in the function. The Function returns a JSON greeting and APIM defines the public API and requires a subscription key.

## Prerequisites

- Azure CLI, authenticated to an Azure subscription with permission to create a resource group, API Management, Storage, App Service, and a Function App.
- `jq`, `curl`, and `zip`.
- Bash (macOS or Linux).

## Resources and SKUs

The deployment creates the following resources in one resource group:

- Azure API Management: **Consumption** tier (pay-per-use; no fixed APIM charge for the included free request allowance).
- Azure Functions: Linux **Consumption (Y1)** plan.
- Azure Storage: **Standard_LRS** StorageV2 account, required by Functions.

Estimated cost is low for occasional lab use, but it is not zero: Azure consumption, storage, and request usage are billed according to the subscription and region. Review the Azure pricing calculator and delete the resource group when finished.

## Deploy

Choose a globally unique, lowercase prefix (3-16 characters; no hyphens) and run:

```bash
cd azure-apim-function-demo
RESOURCE_GROUP=azure-apim-function-demo-rg \
RESOURCE_PREFIX=apimfuncdemo123 \
LOCATION=westeurope \
./scripts/deploy.sh
```

The script prints `RESOURCE_GROUP`, `FUNCTION_APP`, and `APIM_NAME`. APIM creation can take several minutes. The safe parameter template is [infra/parameters.example.json](infra/parameters.example.json); do not commit a real parameters file with environment-specific values.

## Test

After APIM provisioning completes, use the values emitted by deployment:

```bash
RESOURCE_GROUP=azure-apim-function-demo-rg \
FUNCTION_APP=apimfuncdemo123-func \
APIM_NAME=apimfuncdemo123-apim \
./scripts/test-api.sh
```

The test script dynamically retrieves the APIM subscription key for the signed-in operator and never writes it to disk or standard output. It verifies:

1. `GET /api/hello` on the Function returns `200`.
2. APIM request without a key returns `401`.
3. APIM request with a valid key returns `200`.

Example request (supply a key retrieved through an authorized Azure CLI or portal session):

```bash
curl -H 'Ocp-Apim-Subscription-Key: <subscription-key>' \
  'https://<apim-name>.azure-api.net/hello/hello?name=Azure'
```

Expected successful response:

```json
{"message":"Hello, Azure!","backend":"Azure Functions"}
```

## Security considerations

- No keys, connection strings, access tokens, or credentials are stored in this repository.
- APIM subscription keys are gateway credentials; retrieve them only at runtime with an authorized identity.
- The backend route is anonymous to allow APIM to call it without a Function key. For production, add backend access restrictions, private networking, or an authenticated gateway-to-backend design; do not treat a subscription key as a complete authorization solution.
- Consumption APIM does not support `rate-limit-by-key`. Choose a paid APIM tier if rate limiting and HTTP 429 gateway responses are required.
- The Function’s Storage connection string is generated by Azure Resource Manager and is never emitted as a deployment output or committed to Git.

## Cleanup

Delete all demo resources when you finish:

```bash
cd azure-apim-function-demo
RESOURCE_GROUP=azure-apim-function-demo-rg ./scripts/cleanup.sh
```
